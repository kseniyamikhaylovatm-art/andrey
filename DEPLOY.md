# Вход преподавателя и отдельные кабинеты учеников

Сайт уже размещён по адресу https://andrey-dwch.onrender.com/. Код загружается Render из GitHub; обновление считается опубликованным после статуса **Live**.

## Для существующего сервиса Render — один раз

1. Откройте сервис **andrey → Environment → Add Environment Variable**.
2. Добавьте переменную **TEACHER_ACCESS_CODE**. Значение — новый случайный личный код длиной минимум 16 символов, лучше 32. Используйте генератор Render, если доступен, или менеджер паролей. Сохраните код у себя и не передавайте ученикам. Он должен отличаться от прежнего `APP_ACCESS_CODE`. Не присылайте секрет в чат и не сохраняйте в GitHub.
3. Оставьте существующие **APP_ACCESS_CODE** и **SESSION_SECRET**. Сохраните изменения с перезапуском/развёртыванием и дождитесь **Live**.
4. Откройте сайт и войдите с новым личным кодом. Появится **Кабинет преподавателя → Мои ученики**. Если открыт старый ученический вход, сначала нажмите **Выйти**.

`APP_ACCESS_CODE` теперь открывает только существующий общий кабинет **Андрей и Таня** с правами ученика. Материалы и прогресс пары при миграции не разделяются и не очищаются. Старые сеансы без роли попросят повторный вход. Преподаватель не получает права по прежнему общему коду: для этого нужен новый секрет.

Если переменную преподавателя пока не добавили, сайт запустится со старым ученическим кодом, но создание кабинетов будет закрыто. Изменение `render.yaml` само по себе не добавляет переменную в уже созданный вручную Web Service.

## Создание нового ученика

1. Войдите по коду преподавателя и нажмите **Новый ученик**.
2. Введите имя и уровень. По умолчанию кабинет пустой; стартовые учебные примеры можно включить отдельно.
3. Нажмите **Создать кабинет**. Приложение автоматически выдаст личный код ученика.
4. Сохраните его и передайте ученику адрес сайта и только его код. После закрытия окна код больше не показывается. Если он потеряется, нажмите **Новый код входа** в списке учеников: старый код и открытые сеансы перестанут работать, материалы останутся.
5. Преподаватель открывает любой кабинет кнопкой **Открыть кабинет** и возвращается кнопкой **Мои ученики**. Ученик попадает сразу в свой кабинет и не получает доступ к списку учеников, чужим материалам, редактированию плана, уроков и оплат.

Один кабинет может быть кабинетом пары: **Андрей и Таня** остаются вместе. Каждому новому ученику создаётся отдельный кабинет со своим кодом. Преподавателю не нужен новый преподавательский код для каждого ученика.

## Запись слов во время урока

Во время занятия откройте кабинет нужного ученика и вкладку **Слова**. Выберите дату и вводите пары, например `el barrio — район`, нажимая Enter после каждой. Слова сразу сохраняются в датированном списке и в **Автоматизации**. Для повторения именно этой записи нажмите **Тренировать слова урока**. Ученик видит свои списки и переводы; добавление и исправление слов урока доступны только преподавателю. У пары Андрея и Тани список по-прежнему общий внутри их кабинета.

## Бесплатная проба и сохранность

Основной `render.yaml` описывает **Free**, без платного диска. `DATA_DIR=/tmp/mi-espanol-demo`, `DEMO_MODE=true`. Сервер может засыпать; прогресс, созданные кабинеты и их коды могут потеряться после замены временного экземпляра. Это подходит для проверки интерфейса. Не храните здесь единственный экземпляр настоящих учебных материалов и результатов.

Для постоянной работы с учениками нужна SQLite-база на постоянном диске. Отдельный `render-persistent.yaml` описывает платный сервер с диском 1 ГБ. Он не применяется автоматически; стоимость и переход выбираются в Render. При переносе существующего сервиса сначала сделайте согласованную резервную копию SQLite, перенесите базу на диск и сохраните `SESSION_SECRET`. JSON-экспорт выбранного кабинета доступен преподавателю внутри него; автоматического импорта этого экспорта пока нет.

## Новое размещение

Через **New → Blueprint** основной `render.yaml` создаёт пробный сервер, автоматически генерируя отдельные `TEACHER_ACCESS_CODE`, `APP_ACCESS_CODE` и `SESSION_SECRET`. Посмотрите код преподавателя в **Environment**; ученикам выдавайте коды через приложение.

При ручном **New → Web Service**:

- Repository: `kseniyamikhaylovatm-art/andrey`, branch: `main`.
- Runtime: **Node**, instance: **Free** для пробы.
- Build command: `npm ci --include=dev --no-audit --no-fund && npm run build`.
- Start command: `npm start`, health check: `/api/health`.
- `NODE_VERSION=24.19.0`, `NODE_ENV=production`, `HOST=0.0.0.0`.
- `DATA_DIR=/tmp/mi-espanol-demo`, `DEMO_MODE=true` только для пробы.
- `TEACHER_ACCESS_CODE`: случайный секрет от 16 символов; `SESSION_SECRET`: другой случайный секрет от 32 символов.
- `APP_ACCESS_CODE`: необязательный код существующего кабинета пары, от 10 символов. Не используйте для него код преподавателя.

На одном сервере запускается один Node-процесс. Все кабинеты живут в одной SQLite-базе, но доступ к ним проверяется отдельно сервером. Переключение интерфейса и изменение адреса не меняют роль ученика.

## ИИ

Для диалогов, разбора рассказов и автоматического разбора материалов добавьте `ANTHROPIC_API_KEY` только в **Environment**. API оплачивается отдельно от размещения. Карточки, стартовые глаголы, импорт PDF со списком «слово — перевод», кабинеты и статистика работают без него. Приложение обозначает недоступные ИИ-функции явно.
